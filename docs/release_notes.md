# Source release notes

## 2026-10-14

### Source mapping

- `human_pose/`: the available RDPose human-pose source snapshot from the experiment server.
- `spine/hrnet/`: the local HRNet spinal baseline snapshot.
- `spine/rdpose/`: the local RDPose spinal adaptation snapshot.
- `spine/spine3/`: the local RDPose-spine3-fdm snapshot.
- `spine/tools/calc_aasce_pixel_metrics.py`: the existing standalone fixed-pixel evaluation utility.
- `spine/tools/convert_aasce.py`: the original AASCE conversion procedure with command-line paths and explicit validation-list checking.

Original model, training loss, dataset, and inference implementations are preserved. Text encoding and line endings are normalized. Build products generated by Cython, notebook caches, compiled libraries, model files, raw datasets, logs, and unrelated projects are omitted. Third-party license texts and documentation are added.

`source_manifest.json` records source-file hashes. `release_sha256.json` records the distributed text files' hashes, excluding itself. These identify this source release; they do not establish that a checkpoint was trained from these exact files.

### Configuration interpretation

Original YAML settings are retained. The guides specify command-line overrides for paths, GPU count, box sources, validation splits, and optional spinal curve postprocessing. In particular:

1. The human-pose W32 COCO configuration defaults to ground-truth boxes; detector-box evaluation requires an explicit override and detections.
2. The MPII YAML defaults to the test split; validation PCKh requires `DATASET.TEST_SET val` and ground truth.
3. The alpha-0.10 spinal YAML enables curve postprocessing; comparisons must use a declared common postprocessing protocol.
4. AASCE fullcrop annotations are generated from visible ground-truth landmarks. The released 97-image list is a custom validation split.

### Implementation and result scope

Model behavior is defined by the released forward functions. In this human-pose snapshot, HRNet includes feature recalibration on its evaluation path. ResNet's evaluation output and internal computations differ. The function name `_sample_feats_random` alone should not be interpreted as proof of a randomly sampled off-target perturbation policy. This release does not add a new PDM implementation or change forward paths to match a manuscript description.

No new training, inference benchmark, or experiment suite was run during packaging. No checkpoint-to-table mapping or result leaderboard is claimed. Before citing this commit as an exact reproduction of a paper table, preserve and verify the checkpoint, merged configuration, split, box source, decoding settings, and evaluation outputs from the corresponding run.

### Available artifacts

Source code, configurations, documentation, and a filename-only validation list are included. Dataset contents, pretrained weights, trained checkpoints, and generated predictions are separate artifacts and are not present in this repository release.
